# 案件002 kenshin（健診結果作成）

健康診断の **入力 → 自動判定 → 先生の確認 → 受診票・結果のお知らせ・検査内容の説明の印刷** を、院所有の PC 1 台で完結させるプログラムです。
設計の経緯は `docs/cases/002-health-checkup-report/`（調査計画、要件、セキュリティ設計、入力方法、モック）。

- **フォルダを置くだけで動きます。** .NET のインストールは不要。画面は Windows 標準の Microsoft Edge で開きます。
- インターネットに出る通信はありません。看護師のタブレットには、専用 Wi-Fi 越しに入力ページを配ります。
- 判定はすべて設定ファイル（`config\`）のルールで決まります。**AI は判定に使いません。** 音声入力だけ、PC の中で動くオフラインの音声認識（Whisper）を使います（外部送信なし。モデルを入れたときだけ有効）。
- データは `data\kenshin.db` 1 ファイル。起動パスワードがそのまま暗号鍵です。

## できること（段階ごと）

| 段階 | 内容 | 状態 |
|---|---|---|
| M1 | 起動パスワード＝DB 暗号鍵、ネットワーク接続の起動チェック、受診者登録、計測〜問診の入力（PC・タブレット共通画面）、数値項目の自動判定、項目ごとの即時保存、終了時のバックアップ | 実装済み |
| M2 | 所見入力（所見マスターから選択）、所見→判定、総合判定と判定コメント（H・C）の自動提案、受診票 A4 の PDF（QR 付き）、未完了一覧、記録 | 実装済み |
| M3 | 音声入力（限定語彙：数字・なし／あり・プラス／マイナス・つぎ／もどる）。Whisper をプログラム内で実行 | 実装済み（モデルは別途ダウンロード。実機での精度確認は未） |
| M4 | 採血結果の取り込み（HR-f で Print to PDF した文字 PDF、または CSV/テキスト）、受診者との突合、分野別の血液判定、メタボ判定 | 実装済み（HR-f の実物 PDF での読み取り確認は未。架空 PDF と文字列で確認済み） |
| M5 | 結果のお知らせ（A4×4 ページ。小冊子印刷で A3 二つ折り）、検査内容の説明（次回カメラの年数）、確定と発行 PDF の保存、郵送済の記録、要精密の一覧 | 実装済み |

未入手の判定区分マスター・所見マスターは「仮」の値で動いています（`config\判定区分.csv`、`config\所見マスター.csv`）。実物が届いたら差し替えます。

## 配布フォルダのダウンロード方法

1. GitHub のリポジトリで **Actions** タブ → 左の **build-002-cs** → 一番上の実行を開く。
2. 下の **Artifacts** にある `kenshin-002-windows` をクリックしてダウンロード（zip、300MB 前後）。
3. zip を展開し、できた `kenshin` フォルダ（名前は何でもよい）を院所有 PC の消されない場所（例：`C:\kenshin`）に置く。

`main` に変更が入ると自動でビルドされます。手で動かすなら Actions の **Run workflow**。
初めて持ち込む PC でウイルス対策に止められたら、案件001 の README と同じく「復元して除外」をしてください（署名の無い自作プログラムのため）。

## 音声入力のモデルを入れる（任意）

音声入力を使わないなら不要です。モデルは公開されているファイルを **インターネット側の PC で一度だけ**ダウンロードし、USB で運びます。

1. インターネット側の PC のブラウザで次を開き、ファイルを保存する（約 470MB。アカウント不要）。
   `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin`
   より精度を上げたいときは `ggml-medium.bin`（約 1.5GB）。
2. 保存した `ggml-small.bin` を USB で院所有 PC へ運び、配布フォルダの `models\` に置く。
3. `config\config.json` の `voice.modelPath` が `models/ggml-small.bin` になっていることを確認（medium にしたときは書き換える）。
4. 起動すると黒い画面に「音声認識: 有効（ggml-small.bin）」と出る。

モデルは一度置けば更新不要です。Whisper のモデルは MIT ライセンスで、業務利用に問題ありません。

## クリニックの PC でやること（初回）

1. 展開したフォルダを `C:\kenshin` などに置く。
2. `config\config.json` をメモ帳で開き、次を直す。
   - `clinic.name`、`clinic.doctor`（結果のお知らせに印字する実施医師名）、`clinic.occupationalDoctor`（産業医名。無ければ空）
   - `pin`：タブレット用の PIN（4〜6 桁）
   - `listen.lanAddress`：専用 Wi-Fi 側の PC の固定 IP（例 `192.168.50.1`）。タブレットを使わないなら空のまま
   - `backupDir`：終了時に `kenshin.db` を上書きコピーする先（例 `E:\kenshin-backup`）。空なら何もしない
   - `networkGuard`：`true` のまま（ゲートウェイを持つネットワークにつながっていると起動しない）
3. **`run.bat` をダブルクリック**。黒い画面が開き、Edge が起動パスワードの画面を開く。
4. **起動パスワードを決めて入力**（初回に入れたものがそのまま設定される）。これがデータの暗号鍵。忘れると開けないので紙に書いて金庫へ。
5. 左の「＋ 受診者」から登録して使い始める。
6. 終わるときは黒い画面を閉じる（Ctrl+C）。`backupDir` が設定されていればコピーしてから終了する。

### タブレット（看護師用）

1. トラベルルーターをアクセスポイントにして、院所有 PC（有線または Wi-Fi、固定 IP、**ゲートウェイ無し**）とタブレットだけをつなぐ。
2. タブレットのブラウザで `http://<lanAddress>:5080/` を開き、PIN を入れる。
3. 音声入力を使うときは `https://<lanAddress>:5443/` で開く（マイクは https が必要）。初回は `http://<lanAddress>:5080/ca.crt` から証明書をダウンロードし、Android の「設定 → セキュリティ → 証明書のインストール（CA 証明書）」で入れる。

### 採血結果の取り込み

1. HR-f 端末で検査結果画面を「Microsoft Print to PDF」で印刷し、保存先を暗号化 USB にする。
2. USB を院所有 PC に挿し、PDF を配布フォルダの `取込\` に複製する。
3. 画面の「採血の取り込み」または受診者の「血液検査」タブで、読み取った氏名・採取日を見て「この受診者に取り込む」。取り込んだ PDF は `取込\済\` へ移る。
4. 読み取れない PDF（画像だけの PDF、レイアウトが想定外）のときは、同じタブで項目を手入力できる。CSV（項目名,結果,単位,基準値）でも取り込める。

HR-f の印刷レイアウトは実物で未確認です。行の読み方は `src\Kenshin\Lab\FalcoPdfReader.cs` の 1 か所にまとめてあり、実物のサンプルが届いたら合わせます。

## フォルダの中身

| ファイル | 役割 |
|---|---|
| `kenshin.exe` | 起動用（小さい）。本体は `kenshin.dll` と .NET の DLL 群。消さない |
| `run.bat` | 起動。黒い画面を閉じると止まる |
| `開発用（起動チェックなし）.bat` | 開発者の手元用。ネットワーク接続の起動チェックを外す（赤い帯が出る）。配布先では使わない |
| `config\config.json` | 設定（上記） |
| `config\判定基準.json` | BMI・血圧・尿・血液・メタボなどの判定の境界。「仮」の値はマスター入手後に直す |
| `config\判定区分.csv` | 150 異常なし、180 要経過観察 などの区分と重さの順 |
| `config\所見マスター.csv` | 部位ごとの所見コードと、所見から決まる判定 |
| `config\判定コメント.csv` | 判定コメント（H・C）の定型文 |
| `config\コース.json` | コース（企業健診・人間ドックなど）ごとの検査と必須項目 |
| `wwwroot\` | 画面（HTML/JS）。PC もタブレットも同じ |
| `fonts\ipagp.ttf` | 帳票のフォント（IPA P ゴシック） |
| `models\` | 音声認識のモデル（任意） |
| `data\` | `kenshin.db`（暗号化 DB）、`pdf\`（確定時に保存した結果のお知らせ）、`ca.crt`・`cert.pfx`（タブレット用の証明書）。配布物に含めない |
| `取込\` | 採血結果の PDF を置く場所。取り込んだものは `済\` へ |

## 設定の変え方（よくあるもの）

- **判定の境界**：`config\判定基準.json`。例：BMI の区分は `bmi.tiers`、血圧は `bloodPressure.tiers`、尿の（±）は `urine.protein["±"]`。
- **判定区分の重さの順**：`config\判定区分.csv` の `rank`。総合判定は最も rank の大きい区分。現物の結果のお知らせでは「要経過観察」が「要再検査」より重い扱いだったので、その順にしてある。
- **所見の追加**：`config\所見マスター.csv` に行を足す（section, code, text, judgment）。
- **コース**：`config\コース.json`。`sections` が入力する検査、`required` が確定時に警告する必須項目。

## 開発者向け

- ビルド：`dotnet build`。テスト：`dotnet test tests/Kenshin.Tests/Kenshin.Tests.csproj`（60 件、Linux でも動く）。
- 手元で動かす：`dotnet run --project src/Kenshin -- --no-guard --no-browser --port 5080` → `http://127.0.0.1:5080/`。
- 配布用：`dotnet publish src/Kenshin/Kenshin.csproj -c Release -r win-x64 --self-contained true -o dist`（GitHub Actions の `build-002-cs` と同じ）。
- 外向きの HTTP クライアントを使わないことを CI で検査している（`HttpClient` などの参照があれば失敗）。
- 実在の患者情報をテスト・ログ・リポジトリに入れない（CLAUDE.md）。
