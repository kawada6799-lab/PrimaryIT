# 案件002 kenshin（健診結果作成）

健康診断の **入力 → 自動判定 → 先生の確認 → 受診票・結果のお知らせ・検査内容の説明の印刷** を、院所有の PC 1 台で完結させるプログラムです。
設計の経緯は `docs/cases/002-health-checkup-report/`（調査計画、要件、セキュリティ設計、入力方法、モック）。
**ダウンロードから健診当日・採血結果・先生の確認・印刷・更新までを時系列で書いた手順は `docs/cases/002-health-checkup-report/導入から運用までの流れ.md`。**

- **フォルダを置くだけで動きます。** .NET のインストールは不要。画面は Windows 標準の Microsoft Edge で開きます。
- インターネットに出る通信はありません。看護師のタブレットには、専用 Wi-Fi 越しに入力ページを配ります。
- 判定はすべて設定ファイル（`config\`）のルールで決まります。**AI は判定に使いません。** 写真の読み取り（OCR）だけ PC の中で動くモデルを使い、人が確認してから保存します（外部送信なし）。
- データは `data\kenshin.db` 1 ファイル。起動パスワードがそのまま暗号鍵です。

判定区分（150〜195）、判定コメント（H・C）、所見マスター（大腸内視鏡・胃内視鏡・胸部X線・心電図・診察所見、約 5,300 件）は実物です。胃部X線・腹部エコーの所見だけ仮の数行です。所見マスターに判定は付いていないので、所見ありの部位は仮に 180 要経過観察 を付け、先生が変えます。

## 初回だけ：ウイルス対策（Norton など）に止められたら

署名の無い自作プログラムなので、初めて動かす PC では **Norton の「ふるまい検知」が起動用の exe を IDP.Generic として検疫に移す**ことがありました（案件001 と同じ）。危険なものではありません。
そのため今の配布では起動用の exe を作らず、Microsoft 署名付きの `runtime\dotnet.exe` が本体 `kenshin.dll` を動かします。それでも止められたときは次の順に行ってください。

1. Norton を開く → **セキュリティ → 履歴**（または「検疫」）→ 止められたファイルの行を選び → **「復元して除外する」**。
2. 念のためフォルダごと除外する：Norton の **設定 → ウイルス対策 → 「スキャンとリスク」タブ → 「除外/低リスク」** の
   **「スキャンから除外する項目」** と **「自動保護、スクリプト制御、SONAR、ダウンロードインテリジェンスの検出から除外する項目」**（画面によっては「リアルタイム保護から除外する項目」）の両方に、配布フォルダ（例：`C:\kenshin`）を追加。
   ふるまい検知（SONAR）を止めるのは後者です。
3. ファイルが無くなっていたら、zip からもう一度展開する（`data\` と `config\` はそのまま残して、ほかを上書き）。

プログラムは自分でブラウザを起動しません（起動は `run.bat` が行う）。
それでも止められる場合は、Norton の誤検出の報告（https://submit.norton.com/ ）を出すと、同じ exe は以後止まりにくくなります。確実にするにはコード署名証明書（年数万円）ですが、案件が増えてから検討します（技術方針）。

## 配布フォルダのダウンロード方法

1. GitHub のリポジトリで **Actions** タブ → 左の **build-002-cs** → 一番上の実行を開く。
2. 下の **Artifacts** にある `kenshin-002-windows` をクリックしてダウンロード（zip、150MB 前後。プログラム・.NET ランタイム・OCR のモデル）。
3. zip を展開し、できた `kenshin` フォルダ（名前は何でもよい）を院所有 PC の消されない場所（例：`C:\kenshin`）に置く。

`main` に変更が入ると自動でビルドされます。手で動かすなら Actions の **Run workflow**。

### 2 回目以降の更新（zip を手で取らなくてよい）

- **インターネットにつながる PC（手元の PC）**：配布フォルダの **`update-from-github.bat`** をダブルクリック。最新のビルドを取ってきて、動いていれば止め、`data\`・`config\config.json`・`取込\` を残して入れ替え、起動し直します。初回だけ GitHub のトークンを聞きます（GitHub → Settings → Developer settings → Fine-grained tokens → Repository access: PrimaryIT、Permissions: Actions Read-only。`local\github-token.txt` に保存され、リポジトリには入りません）。
- **院所有 PC（インターネット無し）**：手元の PC で **`make-update-usb.bat`** を実行すると `kenshin-update.zip` ができるので USB に入れ、院所有 PC の配布フォルダの **`apply-update.bat`** をダブルクリック（zip は USB のルートに置いたままでよい）。入れ替えて起動し直します。
- 更新できたかは画面右上の「v0.1.0.0（日時）」で分かります。前の `config\` は `backup\config-<日時>\` に残ります（マスターを手で直していたら、そこから戻せます）。
初めて持ち込む PC でウイルス対策に止められたら、案件001 の README と同じく「復元して除外」をしてください（署名の無い自作プログラムのため）。


## 運用の流れ（2026-11-06 先生の決定）

1. **看護師**：入力シート（印刷）に書く → 携帯で撮る → 確認画面で、要確認（赤）の項目だけ紙と見比べて直す → 保存。採血の報告書が届いたら同じように撮る → 確認 → 保存。
2. **先生**：自動判定は見なくてよい。「総合判定・印刷」タブで **所見**（所見タブで入れたもの）と **自動で入ったコメント**（H・C）を確認し、必要なら追加コメントを書く → 「問題なければ保存（確定）」。
3. **印刷**：PC に **USB でつないだプリンター**（複合機に USB 直結）で「3 種まとめて印刷」。ネットワーク印刷はしない。
4. 携帯：**iPhone でも Android でも可**（ブラウザで入力ページを開き「撮る」を押すとカメラが開く。写真は PC へ送るだけで携帯には残らない）。私物の携帯でもよいが、専用 Wi-Fi（インターネットにつながらないトラベルルーター）に WPA2 のパスワードでつなぎ、健診のページ以外に使わない。

## クリニックの PC でやること（初回）

1. 展開したフォルダを `C:\kenshin` などに置く。
2. `config\config.json` をメモ帳で開き、次を直す。
   - `clinic.name`、`clinic.doctor`（結果のお知らせに印字する実施医師名）、`clinic.occupationalDoctor`（産業医名。無ければ空）
   - `pin`：タブレット用の PIN（4〜6 桁）
   - `listen.lanAddress`：専用 Wi-Fi 側の PC の固定 IP（例 `192.168.50.1`）。タブレットを使わないなら空のまま
   - `backupDir`：終了時に `kenshin.db` を上書きコピーする先（例 `E:/kenshin-backup`）。空なら何もしない。パスの `\` は 2 つ重ねて `\\` と書くか `/` にする（1 つだと起動時に「○行目を読めません」で止まる）
   - `networkGuard`：`true` のまま（ゲートウェイを持つネットワークにつながっていると起動しない）
3. **`make-shortcut.bat` を 1 回ダブルクリック**すると、デスクトップに「健診結果作成」のアイコン（ショートカット）ができる。以後はそのアイコンをダブルクリックするだけ。
   - 起動すると黒い画面は最小化され（タスクバーに「kenshin」）、Edge が**アプリの画面**（アドレスバーの無い専用の窓）で起動パスワードの画面を開く。開かなければ手で `http://127.0.0.1:5080/` を開く。
   - 既に起動しているときにもう一度ダブルクリックしても、画面が開くだけ（二重起動しない）。
4. **起動パスワードを決めて入力**（初回に入れたものがそのまま設定される）。これがデータの暗号鍵。忘れると開けないので紙に書いて金庫へ。
5. 左の「＋ 受診者」から登録して使い始める。
6. 終わるときは画面右上の **「終了」** ボタン（PC の画面にだけ出る）。`backupDir` が設定されていればコピーしてから止まる。アプリの窓を × で閉じただけではプログラムは動いたまま（次にアイコンを押せば画面が戻る）。

### タブレット（看護師用）

1. トラベルルーターをアクセスポイントにして、院所有 PC（有線または Wi-Fi、固定 IP、**ゲートウェイ無し**）とタブレットだけをつなぐ。
2. タブレットのブラウザで `http://<lanAddress>:5080/` を開き、PIN を入れる。
3. 撮影の画面でカメラの映像を見ながら撮る（撮影アシスト）には `https://<lanAddress>:5443/` で開く（ブラウザのカメラは https が必要）。初回は `http://<lanAddress>:5080/ca.crt` から証明書を入れる（Android：設定 → セキュリティ → 証明書のインストール。iPhone：ダウンロード後に 設定 → 一般 → VPN とデバイス管理 → インストール、さらに 設定 → 一般 → 情報 → 証明書信頼設定 で有効にする）。http のままでも「撮る」ボタンで端末のカメラアプリが開き、同じように使える。

### 受診票の手書きを写真で取り込む（入力シート）

今までの受診票（手書きの自由記入）は OCR で 7 割程度しか読めないので、**プログラムが印刷する「入力シート」**に書いてもらいます。
シートの先頭に **受診者を決めるマス（個人ID・実施日・生年月日・性別）** があり（2026-11-07）、コースに関係なく同じ並びです。

1. 印刷は 2 通り。**受診者ごと**：受診者を開いて画面下の「入力シートを印刷」（氏名・QR・健診回の番号と、受診者のマスは印字済み）。**白紙**：受診者を開いていない画面の「入力シート（白紙）を印刷」（`/api/sheet/blank`）。白紙は受診者を登録せずに使え、看護師が受診者のマスに個人ID（ファルコの番号）・実施日・生年月日（西暦 8 桁）を書き、性別を塗る。
2. 看護師が書く（受診票のうち看護師が記入する部分だけ：計測・視力・聴力・血圧・尿・便・食後時間）：数字は **1 マスに 1 文字**（右詰め。小数点は印字済み）、選択は **□ を黒く塗る**（✓ ではなく塗りつぶし）。判定は書かない。無い検査の欄は空のまま。問診は受診票の裏面のとおり受診者が書き、所見は先生が画面で入れる。
3. **「📷 入力シートを撮る」** で撮る（受診者を開いた「計測・検査」タブでも、受診者を開いていない最初の画面でもよい。四隅の黒い四角と QR を隠さず、用紙全体が入るように）。
4. 受診者の決め方：印字された健診回の番号が読めればその健診回。読めなければ受診者のマスで探す（個人ID → 無ければ生年月日＋性別）。既存の受診者なら実施日の健診回を開き（無ければ作り）、誰にも一致しなければ **その場で登録する画面**（氏名だけ入れる。生年月日・性別・個人IDはマスの値が入っている）。候補が複数なら選ぶ。
5. 確認画面：□ は墨の量で判定（薄い・2 つ塗りは要確認）、数字は 1 マスずつ読んで範囲（身長 100〜220 など）も見る。要確認は写真の切り抜きと見比べて直す。「この内容で保存」で値と所見が入り、判定が付きます。受診者のマスの値は値としては保存しない（受診者を決めるだけ）。

### 撮影アシスト

- `https://<lanAddress>:5443/` で開くと、「撮る」でブラウザのカメラが起動し、用紙のガイド枠を重ねて撮れます。暗い・ぼけている写真は撮った直後に注意が出て撮り直せます。
- `http://` で開いているときは端末のカメラアプリが開きます（ガイド枠は出ないが、読み取り後の確認画面で四隅の印が見つからない・読めない項目が分かるので撮り直せます）。
- 用紙全体が入り、四隅の黒い四角（入力シート）か表の左右 2 枚（採血の報告書）が隠れないように、影を入れず真上から撮ってください。

### 採血結果の取り込み（報告書の写真。2026-11-06 決定：ネットにつながず全部ローカル）

ファルコから届く紙の報告書を撮って読みます。電カルにも PHC の PC にも触れません。

1. 受診者を開き「血液検査」タブの **「📷 報告書を撮る／写真を選ぶ」** を押す。携帯・タブレット（専用 Wi-Fi で PC につないだもの）ならカメラが起動する。PC なら写真ファイルを選ぶ。1 人 2 枚（1/2 と 2/2）。
   - 真上から、影を入れず、用紙全体が入るように撮る。多少の傾きは問題ない。撮った写真は PC へ送られ、**携帯には残らない**。
2. PC の中の OCR が読む（1 枚 10〜20 秒。外部には送らない）。読み終わると **確認画面** が開く。
   - 報告書は同じ値が左右に 2 回印字されているので、両方を読んで**一致し、基準値と桁も合うものは緑（一致）**。食い違い・片方しか読めない・陽性（＋）・桁が怪しい（小数点の読み落としなど）ものは**赤（要確認）**。
   - 要確認の行は、横の写真の切り抜きと紙を見比べて、値を直すか空にする。読み取った氏名カナ・番号・採取日と、いまの受診者が一致しているかも表示される。
3. **「この内容で保存」**。2 枚目も同じ手順（同じ項目は上書き、ほかは残る）。保存した写真は `取込\済\` へ移る。
4. 写真を使わない場合も、文字の入った PDF・CSV（項目名,結果,単位,基準値）を `取込\` に置けば今までどおり取り込める。手入力は「血液検査の値」の欄に直接打つ。

OCR のモデルは配布 zip の `models\ocr\` に入っています（約 31MB、Apache-2.0）。無ければ写真の読み取りだけ無効になり、ほかは動きます。

## フォルダの中身

| ファイル | 役割 |
|---|---|
| `kenshin.dll` | 本体。`runtime\dotnet.exe`（同梱した .NET、Microsoft 署名付き）で動かす。起動用の `kenshin.exe` は作らない（署名の無い exe はウイルス対策に止められたため） |
| `runtime\` | 同梱した .NET 8 ランタイム。消さない |
| `run.bat` | 起動（黒い画面を最小化し、Edge のアプリ画面を開く）。中身は英語のみ（日本語を書くと cmd が文字化けして動かない） |
| `make-shortcut.bat`・`make-shortcut.ps1`・`kenshin.ico` | デスクトップに「健診結果作成」のショートカットを作る（初回に 1 回）。PowerShell を 1 回だけ使う |
| `run-dev-noguard.bat` | 開発者の手元用。ネットワーク接続の起動チェックを外す（赤い帯が出る）。配布先では使わない |
| `config\config.json` | 設定（上記） |
| `config\判定基準.json` | BMI・血圧・尿・血液・メタボなどの判定の境界。「仮」の値はマスター入手後に直す |
| `config\判定区分.csv` | 150 異常なし〜195 要継続治療 の区分と重さの順（実物）。計測（肥満度）・視力の個別コード（130 痩せ過ぎ、145 眼鏡あり など）も `section` 列で持つ |
| `config\所見マスター.csv` | 部位ごとの所見コードと名称（実物）。`judgment` 列に書けばその所見の判定を固定できる |
| `config\胸部X線所見部品.csv` | 胸部X線の組み合わせコード（位置＋部位＋所見）の部品 |
| `config\血液項目.csv` | 血液検査の全項目の枠（ファルコの報告書の 46 項目。分野・単位・男女の基準値・別名）。項目の少ない健診でも枠は同じで、値の無い枠は画面も印字も空欄 |
| `config\判定コメント.csv` | 判定コメント（H・C）の定型文 |
| `config\コース.json` | コース（企業健診・人間ドックなど）ごとの検査と必須項目 |
| `wwwroot\` | 画面（HTML/JS）。PC もタブレットも同じ |
| `fonts\ipagp.ttf` | 帳票のフォント（IPA P ゴシック） |
| `models\ocr\` | 写真の読み取り（OCR）のモデル 2 ファイル。配布 zip に入っている。消さない |
| `data\` | `kenshin.db`（暗号化 DB）、`pdf\`（確定時に保存した結果のお知らせ）、`ca.crt`・`cert.pfx`（タブレット用の証明書）。配布物に含めない |
| `取込\` | 採血結果の PDF を置く場所。取り込んだものは `済\` へ |

## 設定の変え方（よくあるもの）

- **判定の境界**：`config\判定基準.json`。例：BMI の区分は `bmi.tiers`、血圧は `bloodPressure.tiers`、尿の（±）は `urine.protein["±"]`。
- **判定区分の重さの順**：`config\判定区分.csv` の `rank`（実物の判定ランクの順：150 ＜ 155 ＜ 170 ＜ 175 ＜ 180 ＜ 185 ＜ 190 ＜ 195）。総合判定は最も rank の大きい区分。計測・視力の個別コードは `overall` 列の区分として数える。
- **所見の追加・判定の固定**：`config\所見マスター.csv` に行を足す（section, code, text, judgment）。judgment が空なら「異常なし」系は 150、それ以外は `判定基準.json` の `findings.defaultCode`（仮 180）。
- **血液項目の枠**：`config\血液項目.csv`。行の順が画面と結果のお知らせの並び。`aliases` は取り込んだ項目名の別名（`;` 区切り。HR-f の表記が違ったらここに足す）。`ref_female` が空なら男性と同じ基準値。「仮」と書いた女性の基準値は、女性の報告書が届いたら直す。
- **コース**：`config\コース.json`。`sections` が入力する検査、`required` が確定時に警告する必須項目。

## 開発者向け

- ビルド：`dotnet build`。テスト：`dotnet test tests/Kenshin.Tests/Kenshin.Tests.csproj`（95 件、Linux でも動く。OCR のテストは `models/ocr` にモデルがあるときだけ走る）。
- 手元で動かす：`dotnet run --project src/Kenshin -- --no-guard --no-browser --port 5080` → `http://127.0.0.1:5080/`。
- 配布用：`dotnet publish src/Kenshin/Kenshin.csproj -c Release -r win-x64 --self-contained false -p:UseAppHost=false -o dist` ＋ `dist/runtime` に .NET ランタイムを展開（GitHub Actions の `build-002-cs` と同じ）。
- 外向きの HTTP クライアントを使わないことを CI で検査している（`HttpClient` などの参照があれば失敗）。
- 実在の患者情報をテスト・ログ・リポジトリに入れない（CLAUDE.md）。
