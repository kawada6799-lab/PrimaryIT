# 一般的な健診システムとの比較 ― 今の計画で足りなさそうな部分（2026-11-04）

**2026-11-04 先生の指示：A（先生の確認が要るもの）はいったん止め、リリース後に追加で検討する。** 初回リリースは B と今の要件の範囲で作る。

市販の健診システム（健診センター向け）が普通に持っている機能を並べ、今の計画（`要件.md`、モック 4 画面）と比べた。
「必要かどうか」は先生の健診の種類で決まるので、**まず確認すること**と**あった方がよいもの**と**今回は要らないもの**に分けた。

## A. まず先生に確認すること（やっているなら計画に足す必要がある）

| # | 機能 | 市販システムでの扱い | 今の計画 | 確認すること |
|---|---|---|---|---|
| A1 | **特定健診**（40〜74 歳、保険者が実施主体） | 受診結果通知表の決まった様式、**電子的標準様式（XML）** を支払基金へ提出、階層化（情報提供／動機付け支援／積極的支援）判定 | **無い** | 特定健診を院で受けているか。受けているなら、XML の作成・提出は今どこがやっているか（ファルコ、HR-f、別の代行業者）。院内で作るなら XML 対応が要り、規模が一段大きくなる |
| A2 | **協会けんぽ 生活習慣病予防健診** | 専用の様式と請求（協会けんぽへのデータ提出） | 無い | 受けているか。受けているなら提出データを誰が作っているか |
| A3 | **事業所（企業）への結果提供** | 事業所向けの結果一覧表、健康診断個人票（労働安全衛生規則 様式第 5 号）、産業医の所見欄、就業判定 | 結果のお知らせ（本人向け）だけ | 企業健診で**事業所に何を渡しているか**（結果のお知らせの写し？一覧表？様式第 5 号？）。受診票に産業医名の欄があるので、産業医向けの何かがある可能性 |
| A4 | **自治体のがん検診**（名古屋市など） | 自治体ごとの報告様式・請求 | 無い | 健診と一緒に受けているか。報告は紙で別にやっているなら今回は対象外 |
| A5 | **請求** | 事業所ごとの請求書、本人負担の計算 | 無い | 企業への請求は今どうしているか（HR-f のレセコン部分で出来ているなら不要） |
| A6 | **雇入時健診・特定業務従事者健診**など法定健診の種類 | 種類ごとの必須項目と様式 | コースの概念が無い | どの種類を受けているか。種類ごとに「必須項目が揃っているか」のチェックを入れるかどうか |

**A1 と A3 が最も影響が大きい。** 特定健診の XML は仕様が重く、事業所向けの様式は帳票が 1〜2 種類増える。

## B. あった方がよいもの（小さく足せる。第 1〜3 段階に組み込む）

| # | 機能 | 理由 | 入れ方 |
|---|---|---|---|
| B1 | **コース（健診の種類）とオプションの定義** | 企業健診・人間ドック・オプション（腫瘍マーカー、腹部エコー）で、入力する項目と帳票に出る欄が変わる。コースが無いと空欄だらけの帳票になる | 設定ファイルにコースと項目の対応を持つ。受診者にコースを付ける。モックの「企業健診／人間ドック」の表示をこれにする |
| B2 | **進捗の一覧（日をまたぐ）** | 採血結果待ち・所見待ち・未確定・未郵送が、当日だけでなく過去数週間分見える必要がある。往復が無くなる分、院内で抜けを管理する | 「未完了一覧」画面を 1 つ足す。状態：入力中→所見待ち→血液待ち→確定→郵送済 |
| B3 | **要精密検査・要再検査の追跡** | 判定して終わりではなく、来院したかを追える。クリニックにとって価値が大きい（案件001 と同じ「一覧を出す」型） | 判定が要精密・要再検査・要受診の人を一覧にし、来院日を手で入れる。第 4 段階でよい |
| B4 | **宛名・封筒の印刷と送付記録** | 郵送の手間と宛名の書き間違いが減る | 結果のお知らせと一緒に宛名ラベルを印字。郵送日を記録 |
| B5 | **発行した帳票の PDF 保存と再発行** | 「もう一度ください」「訂正して再送」に対応。訂正前後を両方残す | 確定時に PDF を保存。訂正は版を分ける |
| B6 | **受診者の ID の名寄せ** | ファルコの個人 ID、院の診察券番号、事業所の社員番号が混在する。履歴がつながらないと前回比較が壊れる | 受診者に複数の ID を持たせる。取り込み時はファルコ ID か診察券番号で突合し、迷ったら人が選ぶ（モックの「要確認」） |
| B7 | **法定項目の漏れチェック** | 定期健診の必須項目（身長・体重・視力・聴力・胸部 X 線・血圧・尿・貧血・肝・脂質・血糖・心電図）が未入力のまま確定できないように | コース（B1）の必須項目で判定。警告だけにして確定は止めない設定も可 |
| B8 | **医師名・産業医名の設定** | 帳票に印字する実施医師名。複数医師や産業医名の欄 | 設定ファイル。受診者ごとに上書き可 |
| B9 | **年齢・性別での判定の切り替え** | 血液の基準値は性別で違う。年齢で判定を変える項目（省略可の項目など）もある | 判定基準に性別・年齢の条件を持てるようにする（要件に記載済み） |

## C. 今回は要らないと考えるもの（市販システムにはあるが、このクリニックの規模では不要）

| 機能 | 理由 |
|---|---|
| 予約・受付・会計 | Wakumy と HR-f がある |
| 検査機器との直接連携（心電計、X 線、エコー） | 所見はコードで入力すれば足りる。画像は HR-f や機器側で保存 |
| 問診票の OCR、Web 問診 | 使う問診項目は少ない（服薬・喫煙・飲酒・運動など）ので手入力で足りる |
| 統計（有所見率、労基署の定期健康診断結果報告書の数字） | 事業所が作るもの。求められたら一覧の CSV 出力で対応できる |
| 英語帳票 | 必要になったら文面を設定ファイルで差し替え |
| 紹介状・精密検査依頼書 | HR-f の文書機能で書いている想定。要精密の一覧（B3）から HR-f で書く |
| 複数拠点・複数端末の同時利用 | スタンドアロン 1 台で運用。必要なら共有フォルダに DB を置く形で拡張 |
