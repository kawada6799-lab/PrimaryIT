# 案件002：健康診断結果の判定補助と結果報告書の自動作成 — 調査計画

対象：なごやおなか恒川クリニック。検査会社はファルコバイオシステムズ、電子カルテはメディコム HR-f。
状態：**調査前**。この文書は「何を・誰に・どの順で確認するか」を決めるためのもの。要件は調査後に `要件.md` に書く。

## 先に結論

- **判定（基準値との比較、A/B/C/D などの区分付け）はルールで決定的にできる。** 実行時に AI は要らない。本プロダクトの方針に合う。
- **肝はデータの入口と出口。** ファルコの結果を「人が読む紙」ではなく「プログラムが読めるファイル」で手に入れられるかで、9 割が決まる。
- **作る前に、ベンダーの既製機能で足りないかを先に確認する。** 検査会社が健診の判定・結果表作成を受託している例、電カルに健診帳票や特定健診データ作成の機能がある例は珍しくない。足りるなら作らない。
- **院長の最終確認は残す。** 判定は医療行為なので「プログラムが判定案を出す → 院長が確認・修正 → 確定・印刷」の形にする。自動化するのは転記と一次判定。

## 現状の業務の流れ（2026-11-04 先生のヒアリング、紙の現物から読み取り）

患者の氏名・ID は記録しない。紙の構造だけを書く。

### 登場する紙は 3 種類

| 紙 | 誰が作る | 中身 |
|---|---|---|
| **健康診断受診票**（A4、業者が個人 ID・氏名・生年月日・事業所を印字して用意） | 看護師が今回値を手書き、先生が所見と判定を手書き | 計測（身長・体重・腹囲）、視力、聴力、血圧 2 回、尿（糖・蛋白・潜血・ウロビリノーゲン）、便潜血、肺機能、胸部 X 線・胃部 X 線・心電図・診察所見・内視鏡などの「受診日・所見・判定」欄。血液検査判定（肝機能〜血清）と総合判定の欄もあるが**空欄のまま**。裏面は問診（服薬・既往歴・生活習慣） |
| **ファルコの検査報告書**（A4、2 枚） | ファルコ | 依頼番号、受付日・報告日・採取日時、項目名、結果値、単位、**基準値**、高値 ↑ 印、低値／基準値／高値の * 印。定性項目は「陰性」「(+)」の文字。**紙と同時に電カル（HR-f）にも連携される** |
| **検査内容の説明**（A4 両面、固定） | 院内で用意（印刷物） | BMI〜腫瘍マーカーまで各項目の意味の説明。末尾に次回の胃カメラ・大腸カメラの年数を書く欄 |
| **結果のお知らせ**（A3 二つ折り、健康診断／人間ドック共通） | 業者（どこかは要確認） | 表紙に個人 ID・今回／前回／前々回の健診実施日・実施医師名。中面に全項目の今回／前回／前々回の値と判定（「異常なし」「要経過観察」「要再検査」「正常範囲」）、血液検査判定（肝機能・腎機能・脂質・糖機能・膵機能・血液一般・血清学）、総合判定、判定コメント（定型文）、メタボリックシンドローム判定とコメント |

### 流れ

1. 院内で計測・視力・聴力・血圧・尿を測り、看護師が受診票に手書きする。BMI は余白に手計算。
2. 先生が胸部 X 線・心電図・診察所見・内視鏡の所見を**コード**（V014、0008 のような形）で、判定も**コード**（150、180 のような形）で手書きする。受診票に「判定コメント（マスターより参照願います）」とあるので、コードのマスター表は業者側にある。
3. 採血はファルコへ。結果は紙で届き、HR-f にも入る。
4. 受診票（手書き）とファルコの結果をもとに、業者が「結果のお知らせ」を作って送ってくる。
5. 院内で「結果のお知らせ」に**検査内容の説明**（A4 両面、各項目の意味を書いた固定の紙。末尾に「次回、胃カメラは（　）年後」「次回、大腸カメラは（　）年後」のチェック欄）を同梱し、患者へ郵送する。カメラの年数は手書き。

### 気づいたこと（仮説。次のヒアリングで確かめる）

- 受診票で血液検査判定と総合判定が空欄なのに、結果のお知らせには入っている → **血液の判定は業者側がマスターのルールで自動付与している**可能性が高い。先生が別のタイミングで付けているなら要確認。
- 結果のお知らせの基準値はファルコ報告書と一致 → 採血データは業者へ電子的に渡っている。
- 先生が手で付けている判定は 2 種類に分かれる。
  - **数値から機械的に決まるもの**：計測（BMI）、視力、聴力、血圧、尿、便潜血。→ 完全に自動化できる。
  - **医師の所見が要るもの**：胸部 X 線、心電図、診察所見、内視鏡。→ 所見コードを一覧から選ぶ形にすれば速くなる。判定コードは所見コードから自動で決められる場合が多い。
- 業者が既に「前回比較・判定コメント・メタボ判定・総合判定」まで印字している。**報告書の作成そのものは業者がやっている**ので、自分で報告書を作る必要は無いかもしれない。自動化の本命は「受診票を手書きする前の工程」になる。

### 入手済みのマスター

- **判定コメントマスター**（H001〜H704、C001〜C019）：`判定コメントマスター.md` に転記。総合判定の区分（異常なし／有所見健康／要受診／要再検査／要経過観察／要精密検査／要治療／要継続治療）ごとの定型文と、生活習慣の助言文。
- 未入手：各項目の判定欄に書く数字コード（150、180 など）の**判定区分マスター**、所見コード（V014、0008 など）の**所見マスター**。

### 業者に確認すること（最優先）

1. 結果のお知らせを作っている業者はどこか（ファルコの健診サービスか、別の健診業者か）。
2. 手書きの受診票の代わりに、**電子データ（CSV など）や印字した受診票**を受け付けるか。レイアウト仕様はあるか。
   → 受け付けるなら「看護師が値を入力 → プログラムが BMI と判定コードを自動付与 → 先生は所見だけ一覧から選ぶ → 業者へファイルで送る」が作れ、手書きも業者側の転記も無くなる。
3. **判定区分マスター（150、180 などの数字コード）と所見マスター（V014、0008 など）**をもらえるか。判定コメントマスターは入手済み。判定コードが所見コードや数値からどう決まるかのルール（業者が血液判定に使っているルール）も。
4. 受け付けないなら、受診票を**印字**して渡すのは可能か（手書きより読み間違いが減る）。

### 自動化の候補（流れが分かった時点での案）

| 案 | 何を作るか | 効果 |
|---|---|---|
| 案1 入力＋自動判定 | 閉域 PC 上の入力画面（計測・視力・聴力・血圧・尿）。BMI 計算、判定コード自動付与。先生は X 線・心電図・診察・内視鏡の所見コードを一覧から選ぶ。結果を印字した受診票、または業者指定の CSV で出す | 手書き・手計算・コード暗記が無くなる。業者が CSV を受けるなら転記も無くなる |
| 案2 血液判定の院内確認 | HR-f に入ったファルコ結果（または取込元ファイル）を読み、先生の基準で血液判定の案を一覧にする | 業者が自動判定しているなら不要。先生が手で付けているなら効果大 |
| 案3 自前で結果のお知らせを作る | 業者を使わず院内で A3 帳票まで作る | 業者が既にやっているので当面は作らない。業者の費用・納期が問題になったときの選択肢 |

## 気になっている矛盾（最初に確かめる）

先生からは「検査会社も電カルもインターネット接続が基本できない」と聞いている。一方、ファルコの検査依頼報告システム
**Forest** はクラウド型（インターネット経由）で、各社電子カルテと連携できるとされている（[Forest 紹介ページ](https://www.falco.co.jp/business/forest.html)）。
結果照会システム **TASCAL for ASP** も USB キー + インターネットで照会する仕組み（[TASCAL 紹介ページ](https://www.falco.co.jp/business/it_004_01.html)）。

→ **今、ファルコの結果は実際にどの経路で院に届いているのか**を最初に特定する。候補は次の 4 つで、どれかによって入口の設計が全く変わる。

| 経路 | 入口になり得るもの |
|---|---|
| 紙・FAX のみ | 無し。電子データの提供をファルコに依頼するところから |
| ファルコの受信端末（専用回線 or 閉域内の PC）にデータが届く | その PC 上の**受信ファイルの置き場所** |
| HR-f が外注検査結果として直接取り込んでいる | HR-f の**取込元フォルダ**（取込前のファイル）、または HR-f からの出力 |
| Forest をインターネット側の PC で見ている | Forest からの **CSV/PDF ダウンロード**（インターネット側 PC で処理し、紙で閉域側へ） |

## 調査の進め方（3 本立て）

### 1. 院内の棚卸し（院内だけでできる。最初の 1 週間）

先生に 30 分ヒアリング + 実際の判定作業を 1 回見学して、次を書き出す。見学メモに患者情報は書かない。

- **健診の種類と月間件数**：特定健診、企業健診（定期健康診断・雇入時）、名古屋市の各種がん検診、個人の人間ドック、その他。種類ごとに**報告先**（本人／企業／市／保険者）と**様式**が違う。
- **データが生まれる場所**（項目ごとに「紙」「電カル」「ファルコ」のどれか）：
  問診、身長・体重・腹囲・BMI、血圧、視力・聴力、尿検査（院内か外注か）、心電図、胸部 X 線所見、腹部エコー所見、採血（ファルコ）、便潜血、内視鏡所見。
- **今の報告書**：どの様式か（Excel？電カルの帳票？企業指定の用紙？特定健診の XML 提出？）、誰が何を転記しているか、1 件あたりの所要時間。**現物のサンプル**を匿名化してもらう。
- **判定基準**：今使っている基準表（日本人間ドック学会の判定区分、協会けんぽ、自院独自のどれか。混在も多い）。**総合判定の決め方**（各項目の最悪値か、先生の例外ルールがあるか）。
  学会の判定区分は特定健診の判定値と各学会ガイドラインを基に作られており、A 異常なし／B 軽度異常／C 要経過観察・要再検査／D 要精密検査・要治療が基本
  （[日本人間ドック学会 判定区分の意義](https://www.ningen-dock.jp/ningendock/pdf/Hantei-igi.pdf)）。2 回目以降は前回からの変化で個別判断が要るとされているので、**経年比較は第 2 段階**に回す。
- **先生の作業の流れ**：「どこから何を見て、どこに何を書くか」をステップで記録。ここが自動化対象そのもの。

### 2. 検査会社（ファルコ）に聞くこと

営業担当に次の質問リストを送る。**ファイル仕様書とダミーデータのサンプル**をもらうのがゴール。

1. 今、当院への結果はどの経路で届いているか（紙／FAX／受信端末／Forest／HR-f 直接取込）。
2. 結果を**電子データ**で受け取れるか。形式は何か（JAHIS 臨床検査データ交換規約〔HL7 v2.5 ベース〕／貴社独自の固定長／CSV）。どこに届くか（受信 PC のフォルダ／ダウンロード）。
3. データに含まれる項目：**当院の診察券番号**が入って戻ってくるか、検査日、項目コード（JLAC10 など）、結果値、単位、**基準値（性別・年齢別か）**、**H/L フラグ**、依頼時のコース名。
4. 依頼時に「健診」区分やコース名を伝えられるか。結果に健診フラグが付くと、診療の採血と健診の採血を分けて抽出できる。
5. **健診向けサービス**の有無：健診の一括判定・結果報告書作成の受託、健診システムの提供、特定健診の電子的標準様式（XML）作成支援。
6. 受信端末を使っている場合、その PC に自作プログラムを置いてよいか。回線は専用線か。
7. 仕様書（レコードレイアウト）と、**架空患者のサンプルデータ**を提供してもらえるか。

### 3. 電子カルテ（メディコム HR-f）に聞くこと

PHC または販売店の担当に次を聞く。メディコムは外注検査会社・検査機器との結果取込連携を持つ
（[Medicom-HRf 検査機能](https://www.phchd.com/jp/medicom/clinics/mchrf-hybrid-cloud/function-detail/examination)、
[集計・検索機能](https://www.phchd.com/jp/medicom/clinics/mchrf-hybrid-cloud/function-detail/summarize)）が、
**ファイル出力の有無と形式**は公開資料に無い。

1. ファルコ結果の取込を使っているか。使っていれば**取込元ファイルの置き場所と形式**（取込前のファイルがそのまま入口になる）。
2. **データ出力機能**：患者基本情報・検査結果の CSV／テキスト出力、集計・検索結果のファイル出力、帳票の PDF・ファイル出力。
3. **SS-MIX2 標準化ストレージ**への出力の有無（オプションか、費用）。あれば検査結果（OML/OUL）・患者基本（ADT）を標準形式で読める。
4. **健診機能**：健診結果報告書の帳票、特定健診データ（XML）作成、判定機能。あるなら「作らない」が選択肢になる。
5. 身体計測・血圧・問診は電カルに入力しているか。入力しているなら抽出対象。紙なら入力画面を別途作る。
6. 電カル PC に**自作プログラム（.NET のフォルダ、インストール不要）を置いてよいか**、USB メモリの使用可否、サポート上の制約。ベンダーに事前に一言入れるのは技術方針どおり。
7. 判定結果や総合コメントを電カルに**書き戻す手段**があるか（おそらく無い → 報告書を PDF/紙で保管、または人が転記）。

## データの流れの候補（回答が揃ってから選ぶ）

優先順位は技術方針どおり **ファイル連携 > API > ブラウザ自動化 > 画面操作**。

| 案 | 流れ | 条件 |
|---|---|---|
| 案0 既製 | ファルコ／メディコムの健診サービスで判定・報告書まで済ませる | ベンダーに該当サービスがあり、様式が合う |
| **案A ファイル連携（本命）** | ファルコ結果ファイル（受信 PC か HR-f 取込元）＋ 院内入力（計測・問診・所見を Excel/CSV に）→ **C# ツールが判定案と報告書（Excel/PDF）を作る** → 院長が確認・修正 → 印刷 | 結果がファイルで手に入り、診察券番号で突合できる |
| 案B HR-f 出力連携 | HR-f から患者＋検査結果を CSV／SS-MIX2 で出し、それを入口にする | HR-f に出力機能がある |
| 案C 画面操作（最後の手段） | HR-f の検査結果画面を C# + FlaUI で読む | 上記が全部無理なとき。壊れやすい |

どの案でも **閉域ネットワーク内の PC で完結させる**。インターネット側に患者データを出さない。
Forest をインターネット側で見ている経路の場合だけ、インターネット側 PC で処理して紙／PDF で閉域側へ渡す形になる。

## 判定ロジックの作り方（案 A/B/C 共通）

- 判定基準は**設定ファイル**（CSV か JSON）に持つ：項目コード、性別・年齢条件、A/B/C/D の境界値、付けるコメント文。学会の判定区分を土台に、**院の基準で上書き**できるようにする。
- 総合判定：各項目の最悪値を基本に、先生の例外ルール（例：喫煙者の○○は一段上げる）を設定で追加。
- 自由記述（所見コメント）は**定型文の組み合わせ**＋先生が編集。実行時に AI で文章を生成しない。
- **検証**：過去 20〜30 件分の結果を**匿名化**（患者 ID を連番に、氏名削除、生年月日は年齢のみ）して、プログラムの判定と先生の判定を突き合わせる。
  食い違いは基準表の書き漏れなので、基準表を直して一致率を上げる。この突き合わせ結果を先生に見せて納得してもらうのが導入の鍵。
- 経年比較（前回値との差、変化率）は第 2 段階。

## 個人情報・運用の注意

- 設計の最優先は**電カルネットワーク内で完結**。3 省 2 ガイドラインの観点から、閉域網から外部へ患者情報を送らない。
- 開発・テスト用データは匿名化してから手持ち PC に移す。リポジトリには入れない（`local/`）。サンプルはベンダーの架空データを優先。
- 配布物は技術方針どおり **.NET 8 self-contained のフォルダ 1 つ**（インストール不要、管理者権限不要、単一 exe にしない）。
