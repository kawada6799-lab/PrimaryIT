# セキュリティ設計（2026-11-04 初版 → 同日 簡素化）

## 決定（2026-11-04 先生）：簡素化版で作る

先生の方針：**人的なミスは運用で見る（プログラムでは対策しない）。利用者の役割分け・自動ロック・世代バックアップ・復元機能は要らない。起動時にパスワードを求めれば十分。**

これを受けて初回リリースは次の形にする。

| 項目 | 簡素化版（これで作る） | 外したもの |
|---|---|---|
| 入口 | **起動時にパスワードを 1 つ求める**（全員共有） | 役割（看護師／医師／管理者）、利用者ごとのアカウント、15 分の自動ロック |
| データ | **起動パスワードをそのまま DB（SQLite）の暗号鍵にする**。SQLCipher を接続文字列で有効にするだけで、追加の画面・鍵管理は無し。パスワードを忘れると開けないので紙で金庫に保管 | DPAPI による鍵の保護、二重化の設計 |
| バックアップ | **終了時に DB ファイル 1 つを指定フォルダ（USB など）へ上書きコピー**。無ければ何もしない。戻すときはファイルを元の場所に置くだけ | 30 日＋月次 12 か月の世代、復元機能、復元テストの運用 |
| 記録 | 「いつ・何を」（確定・確定解除・印刷・取込）の簡単な記録だけ残す。誰が、は残らない | 監査証跡としての操作ログ、変更前後の値、CSV 出力 |
| PC | BitLocker を Windows の設定で有効にする（コード無し）。ネットワークに接続しない | ファイアウォール規則の案内、オフライン更新の台帳 |
| USB | 暗号化 USB 1 本。取り込んだ PDF はプログラムが消す | 紛失時の手順書、2 人照合、運用ルールの掲示 |
| プログラム | 通信 API を使わない（CI で検査）。PDF は文字抽出のみ。依存ライブラリは最小・固定 | 変更なし |
| 帳票 | 全ページのフッターに ID と氏名（取り違えに気づける最低限） | 封入チェック一覧、宛名ラベルの必須化 |

受け入れるリスク（先生了解済みとする）：
- 共有パスワードなので「誰が判定を変えたか」は分からない。
- バックアップは最新 1 世代だけ。壊れた DB を上書きコピーすると戻せない（終了時コピーの前に DB が開けることを確認してからコピーする、という最低限の保護だけ入れる）。
- 封入の取り違え・USB の紛失は運用で見る。

以下は初版の検討内容。簡素化で外したものも、理由とともに記録として残す。

---

対象：案件002 健診結果作成プログラム。院所有のスタンドアロン PC で動かし、HR-f から Print to PDF で出した採血結果を暗号化 USB で運ぶ構成
（`受け取り方法とセキュリティ.md` で決定済み）。
この文書は「どんな形でセキュリティを担保するか」を、**プログラムが実装すること**と**クリニックが運用で守ること**に分けて決めるもの。

## 1. 守るもの

| 守るもの | 中身 | 漏れたとき・壊れたときの影響 |
|---|---|---|
| 受診者の健診データ | 氏名・生年月日・事業所・計測値・所見・判定・血液検査値 | **要配慮個人情報**（個人情報保護法）。漏えいは個人情報保護委員会への報告と本人通知の対象 |
| 判定の記録 | 誰がいつどの判定を付け、確定したか | 改ざん・消失は医療記録としての信頼を失う。健康診断個人票は 5 年保存（労働安全衛生規則） |
| 発行した帳票 | 結果のお知らせの PDF | 再発行・訂正の根拠 |
| プログラムそのもの | 判定ロジック、設定、依存ライブラリ | 改変されると誤った判定が印字される |

## 2. 前提の構成（決定済み）

```
[HR-f 端末（PHC 管理）] --Print to PDF--> [暗号化 USB] --> [院所有 PC（スタンドアロン）] --> [プリンタ] --> 郵送
                                                                 |
                                                        [暗号化バックアップ媒体]
```

- 院所有 PC はどのネットワークにもつながない。Wi-Fi・Bluetooth 無効。
- プログラムは外部と通信する機能を一切持たない（更新確認も無い）。
- 実行時に AI を使わない。判定は決定的なルール。

## 3. 脅威と対策

| # | 脅威 | 起きやすさ | 対策（技術） | 対策（運用） |
|---|---|---|---|---|
| T1 | PC の盗難・紛失 | 低（院内設置） | **BitLocker でディスク全体を暗号化**。ログインパスワード必須。15 分で画面ロック | スタッフ専用の部屋に置く。画面が患者から見えない向き |
| T2 | USB の紛失 | **中**（毎回運ぶ） | **暗号化 USB**（ハードウェア暗号化か BitLocker To Go）。USB には PDF だけ置き、取り込んだら消す。DB・バックアップは別媒体 | 専用 1 本に限定、他用途禁止。紛失時の手順を 1 枚にして掲示 |
| T3 | USB 経由のマルウェア | 低〜中 | 自動実行無効。プログラムは **.pdf 以外のファイルを読まない**。PDF は文字抽出だけ行い、スクリプトや埋め込みを実行しない。サイズ上限 | 院所有 PC では USB を「取込フォルダへ複製」以外に使わない |
| T4 | スタッフの不正閲覧・誤操作 | 低〜中 | **利用者ごとのアカウントと役割**（看護師＝入力、医師＝判定・確定、管理者＝設定）。**操作ログ**（誰が・いつ・誰の・何を）。確定後の判定は医師の「確定解除」なしに変更不可 | 共有アカウント禁止。退職時にアカウント停止 |
| T5 | 判定・記録の改ざん | 低 | 確定した健診回は読み取り専用。操作ログは追記のみ。訂正は新しい版を作り、旧版を残す | 訂正は医師が理由を入力 |
| T6 | ディスク故障・誤削除によるデータ消失 | 中（年単位） | **暗号化バックアップ**を日次で別媒体へ。世代（直近 30 日 + 月次 12 か月）。復元手順をプログラムに内蔵 | 月 1 回、復元が出来るか確認。バックアップ媒体は PC と別の場所（金庫）に保管 |
| T7 | プログラムの改変・供給網（依存ライブラリ） | 低 | 依存ライブラリは最小限でバージョン固定。GitHub Actions でソースからビルドし、配布フォルダのハッシュを記録。**HttpClient などの通信 API を使わない**ことをテストで検査。Windows ファイアウォールで exe の送受信を遮断（念のため） | 配布フォルダの置き換えは管理者だけ。ハッシュを照合 |
| T8 | 郵送の取り違え（別人の結果を封入） | **中**（人手） | 全ページのフッターに個人 ID と氏名、宛名ラベルも同じ記録から印字。封入チェック用に「ID・氏名・ページ数」の一覧を出す | 封入時に 2 人で照合（宛名と中身の ID）。郵送日を記録 |
| T9 | 印刷物・PDF の放置 | 中 | 発行 PDF は暗号化された DB と同じディスク内のフォルダに限定。デスクトップに出さない | 印刷物は当日中に封入。ミスプリントはシュレッダー |
| T10 | HR-f 端末に PDF が残る | 中 | — | Print to PDF の保存先を**USB に直接**指定。HR-f 端末のディスクに保存しない |
| T11 | Windows の未更新（スタンドアロンのため） | 低（ネットワーク非接続） | 攻撃面が USB の PDF だけなので許容。年 1〜2 回、オフライン更新（更新ファイルを USB で持ち込む） | 更新日を台帳に記録 |
| T12 | PC・USB の廃棄 | 低 | BitLocker の鍵を破棄すれば読めない | 廃棄時はディスクの物理破壊か完全消去。記録を残す |
| T13 | 開発中の患者情報の混入 | 中 | リポジトリ・テストデータ・ログ・モックは**架空の値のみ**。ログに氏名・生年月日を書かない（内部 ID のみ）。クラッシュ時のダンプを取らない | 実データでの検証は院所有 PC 上だけ。開発者は実データを持ち出さない |

## 4. プログラムが実装すること（初版の案。簡素化版は冒頭の表が優先）

### 4.1 データの保護

- DB は SQLite 1 ファイル。**SQLCipher（AES-256）で暗号化**。鍵は Windows の DPAPI（ログインユーザーに紐づく）で保護して保存。BitLocker と二重。
- 発行した PDF と添付（あれば）も同じ暗号化領域に置く。平文の一時ファイルは作らない（作るなら終了時に消す）。
- 取込フォルダの PDF は、取り込み成功後にプログラムが削除（確認付き）。

### 4.2 利用者と権限

| 役割 | できること |
|---|---|
| 看護師 | 受診者の登録、計測・問診の入力、PDF の取り込み、受診票の印刷 |
| 医師 | 上記に加え、所見・判定の入力と変更、総合判定、確定・確定解除、結果のお知らせの印刷 |
| 管理者 | 上記に加え、利用者の追加・停止、判定基準・コード表・帳票文面の変更、バックアップと復元 |

- ログインはプログラム内のアカウント（Windows アカウントとは別）。パスワードはハッシュ（PBKDF2 か Argon2）で保存。
- 15 分無操作でロック。

### 4.3 操作ログ（監査証跡）

- 記録する：日時、利用者、操作（登録・入力・判定変更・確定・確定解除・印刷・取込・設定変更・ログイン失敗）、対象（受診者の内部 ID と健診回）、変更前後の値（判定について）。
- 追記のみ。管理者でも削除不可。画面から検索・CSV 出力できる。
- 電子保存の 3 原則への対応：**真正性**（誰が・いつ・改ざん不可）、**見読性**（いつでも画面表示・印刷）、**保存性**（暗号化バックアップと世代）。

### 4.4 入力の安全

- PDF の読み取りは文字抽出のみ（PdfPig などの純粋なパーサ）。JavaScript・外部参照・添付は無視。1 ファイル 20MB まで。
- 読み取った値は必ず画面で人が確認してから保存（自動では確定しない）。
- 設定ファイルは起動時に検証し、壊れていれば既定値で起動して警告。

### 4.5 通信を持たない

- ネットワーク関連の API を使わない。ビルド時に `System.Net.Http` などへの参照が無いことを自動検査する。
- 初回起動時に Windows ファイアウォールの送受信遮断ルールを案内（管理者権限が要るので手順書に）。

### 4.6 バックアップと復元

- 日次（終了時）に暗号化された DB と PDF を指定の媒体へ複製。直近 30 日 + 月次 12 か月。
- 「復元」機能をプログラムに内蔵し、別の PC でも復元できる（PC 故障時）。鍵は管理者のパスフレーズからも導出できるようにし、DPAPI だけに依存しない。

## 5. クリニックが運用で守ること（初版の案。先生の方針により掲示は任意）

1. 院所有 PC はネットワークにつながない。USB は専用の暗号化 USB 1 本だけ。
2. HR-f で PDF にするときは保存先を USB にする。HR-f 端末には残さない。
3. 取り込んだら USB の PDF は消す（プログラムが行う）。
4. アカウントは本人のものだけ使う。離席時はロック。
5. 封入は宛名と中身の ID を 2 人で照合。郵送日を記録。
6. バックアップ媒体は金庫。月 1 回、復元できるか確認。
7. BitLocker の回復キーと管理者パスフレーズは紙で金庫。
8. 紛失・誤送付が起きたら、すぐ院長に報告し、記録（いつ・何を・誰に）を取る。
9. 年 1〜2 回、Windows のオフライン更新。台帳に記録。
10. 退職者のアカウントは当日停止。

## 6. 開発側のルール（このリポジトリ）

- 実在の患者情報をリポジトリ・テスト・モック・Issue・チャットに書かない（CLAUDE.md のとおり）。写真から転記するのはコード表と様式だけ。
- 依存ライブラリは必要最小限（SQLite + SQLCipher、PDF 文字抽出、PDF 生成、UI）。バージョンを固定し、更新は差分を読んでから。
- 配布は GitHub Actions のビルド成果物。ハッシュを README に記録。単一 exe にしない（技術方針）。
- 認証情報は無い構成にする（外部サービスを使わないため）。

## 8. 受け入れる残りのリスク（先生に了解してもらう）

- スタンドアロンのため Windows の更新が遅れる。攻撃面が USB の PDF だけなので許容する。
- 封入の取り違えは技術だけでは防げない。2 人照合の運用に頼る。
- 院所有 PC 1 台に依存する。故障時はバックアップから別 PC に復元する（復元手順を内蔵）。復旧まで最大 1 日。
- 開発者（1 名）に依存する。ソースと設計文書をリポジトリに残し、配布フォルダのビルド手順を自動化しておく。

## 10. 決めてもらうこと（簡素化版）

1. 起動パスワードを決める人と、紙での保管場所。
2. 暗号化 USB の種類（ハードウェア暗号化、または普通の USB に BitLocker To Go）。
3. バックアップのコピー先（2 本目の USB か、外付け SSD）。無しでも動くが、推奨は有り。
