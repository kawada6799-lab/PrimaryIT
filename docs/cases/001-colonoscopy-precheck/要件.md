# 案件001：大腸内視鏡の Web 予約患者で「事前診察予約」が無い人を見つけて通知する

## 困っている人と場面

- **誰が**：院長と看護師
- **何が**：患者が Wakumy から大腸内視鏡の予約を取っても、セットで必要な「大腸カメラ事前診察」の予約を取ってくれないことがある。
- **今の対応**：予約が入るたびに、その患者を Wakumy で検索して事前診察予約があるか目で確認している。

## やりたいこと

1. Wakumy の「予約通知一覧」に **通知種別 = 予約確定時** の通知が新しく入ったら検知する。
2. その予約が **大腸内視鏡** の予約かどうかを確認する。
3. 大腸内視鏡の予約なら、同じ患者に **大腸カメラ事前診察** の予約があるか確認する。
4. 直近30日の範囲で事前診察予約が無い患者を集めて、**診察券番号と氏名の一覧**で知らせる（当初はメール案、後にファイル出力に変更）。

## 動かす場所

- Wakumy（クラウド）を見るだけなので、**手持ちPC（インターネット側）**で動かす。→ 言語は Python。
- 電カルネットワークには一切触れない。

## 実行時に AI は必要か

- **不要。** 通知の種別判定、メニュー名の照合、患者の突合はすべて文字列の比較で決定的にできる。
- AI を使うのは開発時のみ（この文書作成、画面構造の読み取り、コード生成）。

## 方式変更（2026-10-08）：予約通知一覧 → 予約一覧（内視鏡タブ）起点に

実機で分かったこと：患者管理で見つからない患者は **初診で患者登録が無い人**で、その人も大腸カメラを Web 予約できる。
通知 → 患者管理 → 患者ページ、の流れでは初診の人（事前診察を知らない本命）が構造的に漏れる。

新しい流れ（`--mode schedule`、既定）：

1. 予約一覧 → **内視鏡タブ**を日表示で今日から 45 日先まで 1 日ずつ見て、「大腸」を含む予約（連鎖用は除く）を集める。初診も含めて全員ここに入る。
2. 予約一覧 → **外来診察タブ**を 30 日前から 45 日先まで見て、「大腸カメラ事前診察」を集める。過去を見るのは、検査が間近な人の事前診察は既に済んでいるため。
3. 診察券番号で突合。初診で番号が無い人は **氏名＋生年月日** で突合。事前診察が無い検査予約を一覧に出す。

患者管理も通知一覧も使わないので、名前検索の失敗と通知 100 件上限の問題は消える。旧方式は `--mode notifications` で残す。

## ※要チェック※（2026-10-10 先生の指示）

最終結果（事前診察が無い検査予約）の中から、次のどちらかに当てはまる人を一番下に「※要チェック※」として別にまとめる。

- 過去 1 か月（30 日）以内に外来診察タブに一度も出てこない人（キャンセル行は数えない）。外来を受診していれば先生が直接話せているため、受診が無い人を優先する。
- 診察券番号が未登録の人（初診）。

## 決めた判定ルール（画面から読み取って仮決め。config.toml で変更可）

- 検査予約：予約メニューに「大腸」を含み、ステータスが「予約」。「連鎖用」「事前診察」を含むものは除外。
- 事前診察：予約メニューに「大腸カメラ事前診察」を含み、ステータスが「予約」または「来院」。
- 検査日の前 30 日以内（当日含む）に事前診察があれば OK。無ければ一覧に載せる。
- 対象にする通知は「予約確定時」で、通知完了日時が 5 日以内のもの（4日おき実行 + 余裕1日）。処理済みの予約IDは記録して二度見ない。

## 先生と決めたこと（2026-10-07）

- **知らせ方**：メールはやめ（Gmail のアプリパスワード設定が手間）、**診察券番号と氏名の一覧をテキストファイルに書いてメモ帳で自動的に開く** + Windows 通知。
  アカウント不要。共有フォルダに出せばスタッフ全員が見られる。メールは任意機能として残す。
- **事前診察の「3日前まで」ルール**：不要。事前診察の予約が無い人を出力するだけでよい。最終的には電話で直接連絡する。
- **実行間隔**：**4 日に 1 回**。先生のPCにプログラムを入れ、タスクスケジューラで動かす。Claude は実行時に関与しない。
  → 予約通知一覧を複数ページ読み、通知完了日時が 5 日より古いところで打ち切る設計にした。
- **Wakumy の CSV 出力 / API**：無い。
- **利用規約**：管理画面の自動操作は問題ない（先生確認済み）。
